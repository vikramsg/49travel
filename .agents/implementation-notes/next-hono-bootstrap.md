# Next.js + Hono bootstrap — implementation notes (layer 3)

Stack layer 3. Plan: `.agents/plans/map-tab-nextjs-migration.md`, Phase 3. The plan
file is frozen; this file records what was verified and every decision that was
not already agreed.

## What the layer had to achieve

Replace CRA with a Next.js App Router project at the repo root (TypeScript,
Tailwind, shadcn/ui), port the four components without changing their content or
behaviour, introduce the single city manifest and router-based `TopBar`, mount
Hono over native DuckDB reading the committed Parquet, and retire CRA and its
dead weight.

## Decisions not already agreed

Each item: the decision, why, and where it lives.

### 1. The €49 JSON is imported from `python/data/travel49/`; `src/data/` is gone

- **Decision:** `lib/cities.ts` loads each origin's JSON from
  `python/data/travel49/<slug>.json`, and the root `Makefile`'s `cp … src/data`
  step is removed.
- **Why:** `src/` is retired, so the app data had to move. Copying the generated
  JSON into a second frontend directory would be a second source of truth for the
  same bytes. Importing the generator's own output means `make city_json` is what
  the app reads, with no copy step. This is the location fix the plan's coupling
  note assigns to whichever layer deletes `src/`.
- **Where:** `lib/cities.ts`, `Makefile`, `AGENTS.md`.

### 2. The manifest carries a lazy destination loader, not static JSON imports

- **Decision:** each manifest entry has `loadDestinations: () => Promise<…>`
  wrapping a dynamic `import()`.
- **Why:** the seven JSON files total ~2.9 MB. A static import in the manifest
  would pull all of them into the Home page's render because Home imports the
  manifest for its names. The dynamic import keeps each origin's data on its own
  route and Home's payload to the seven names.
- **Where:** `lib/cities.ts`.

### 3. `latitude`/`longitude` are in the manifest but have no consumer yet

- **Decision:** included as the plan's Tidy First item 3 names them.
- **Why, and the reason this needs review:** nothing in layer 3 reads them. Home
  and CityPage show names and times; the map's origin selector in layer 4 reads
  the 103 origins from `city.parquet`, not this manifest. They are the one part of
  the manifest that is currently unreferenced. I kept them because the plan and
  the layer brief both name coordinates as manifest fields, but if they stay
  unused they are dead data and should be dropped until the map needs them.
- **Where:** `lib/cities.ts`.

### 4. `originStopId` from the manifest replaces the per-card `origin_stop`

- **Decision:** `CityPage` builds its bahn.de link from `origin.originStopId`
  rather than from `destination.origin_stop`.
- **Why:** it makes the manifest's origin stop id the value the page actually
  uses, instead of a second declaration nothing reads. Verified equivalent: every
  card in each of the seven generated files carries the same `origin_stop`, and
  it equals the manifest value.
- **Where:** `lib/cities.ts`, `components/city-page.tsx`.

### 5. Primary colour is Bootstrap blue

- **Decision:** `--primary` is `#0d6efd` in `app/globals.css`.
- **Why:** the navbar and the buttons in the CRA baseline are Bootstrap's blue.
  This is a theme token rather than per-element styling, so the design system
  stays in charge; it is what makes the port visually faithful.
- **Where:** `app/globals.css`.

### 6. `--font-sans` is set to the system stack

- **Decision:** `:root` defines `--font-sans` as the CRA body stack
  (`-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, …`).
- **Why:** shadcn's generated theme has `--font-sans: var(--font-sans)`, a
  self-reference that expects a font loader to define the variable. Without one
  the pages fell back to a serif. The baseline used system fonts, so the system
  stack is both the fix and the faithful choice.
- **Where:** `app/globals.css`.

### 7. The expand toggle is a real button, and multiple cards may stay open

- **Decision:** the caret is a `<button>` with `aria-expanded`, an `aria-label`
  naming the city, and a visible focus ring. Expanded state is a `Set` of visible
  card indices.
- **Why:** the CRA toggle was a `div` with `onClick`, unreachable by keyboard,
  which `.agents/UX.md` forbids. A `Set` preserves the CRA behaviour that any
  number of cards can be open at once; a single "expanded index" would have
  silently changed it.
- **Where:** `components/city-page.tsx`.

### 8. Pagination is derived, not a second piece of state

- **Decision:** `hasMore` is `visibleCount < destinations.length`; the CRA's
  separate `showButton` state and its `useEffect` are gone.
- **Why:** the effect only computed what the comparison already gives. Behaviour
  is unchanged.
- **Where:** `components/city-page.tsx`.

### 9. The GitHub mark is an inlined SVG

- **Decision:** `components/github-icon.tsx` draws the octocat.
- **Why:** lucide-react v1 carries no brand marks, and adding an icon package for
  one glyph is not worth it.
- **Where:** `components/github-icon.tsx`.

### 10. `/api/health` is the proof endpoint

- **Decision:** Hono exposes `GET /api/health` returning
  `{ status, cityCount }`, where `cityCount` is read from `city.parquet` with
  native DuckDB.
- **Why:** the layer has to prove the Hono route and the Parquet read work;
  `/api/reachable` is layer 4 and was deliberately not built. This endpoint is the
  observable proof and is the seed for layer 4's client.
- **Where:** `app/api/[[...route]]/route.ts`.

### 11. One DuckDB connection per warm server instance

- **Decision:** `lib/duckdb.ts` caches the `DuckDBConnection` promise at module
  scope.
- **Why:** opening an in-memory database and its native binding per request costs
  more than the queries this dataset needs. Warm serverless invocations reuse the
  module, so the connection is shared.
- **Where:** `lib/duckdb.ts`.

### 12. The native module and Parquet are traced, not bundled

- **Decision:** `next.config.ts` sets `serverExternalPackages: ["@duckdb/node-api"]`
  and a root-wide `outputFileTracingIncludes` covering the Parquet files plus
  `duckdb.node` and its adjacent `libduckdb` shared library for the installed
  platform.
- **Why:** `@duckdb/node-api` loads a platform `.node` binding, so it must stay
  out of the bundle; the binding in turn loads `libduckdb` at runtime, and the
  Parquet must ship inside the function. The first Vercel preview traced
  `duckdb.node` but omitted `libduckdb.so`, causing `/api/health` to return 500.
  The explicit shared-library glob fixes that. Verified in
  `.next/server/app/api/[[...route]]/route.js.nft.json`: the three Parquet files,
  the platform binding and `libduckdb.dylib` are traced locally; Vercel installs
  and traces the Linux equivalents.
- **Where:** `next.config.ts`.

### 13. A not-found page was added

- **Decision:** `app/not-found.tsx` with a link back to the city list.
- **Why:** the dynamic origin route now calls `notFound()` for an unknown slug.
  CRA had no 404 at all; `.agents/UX.md` says every dead end must say what to do
  next.
- **Where:** `app/not-found.tsx`.

### 14. The two analytics that existed are preserved; the third is not

- **Decision:** Vercel Analytics via `@vercel/analytics/next`, and the Umami
  script via `next/script` in the layout. The CRA `vitals.js` `sendBeacon` path and
  `.env.production` are deleted.
- **Why:** `vitals.js` was CRA-only and duplicated what `@vercel/analytics`
  already sends. The Umami script and the Vercel component were in the CRA head
  and body, so removing them would change production behaviour.
- **Where:** `app/layout.tsx`.

### 15. `public/manifest.json` updated, `favico.ico` renamed

- **Decision:** the PWA manifest's `name`/`short_name` now describe this app
  instead of the CRA sample, and `favico.ico` became `favicon.ico`.
- **Why:** the misspelling made browsers request `/favicon.ico` and get a 404;
  the stock manifest named a "React App" that no longer exists. `logo192.png`,
  `logo512.png` and `robots.txt` are kept.
- **Where:** `public/`.

### 16. eslint ignores the non-frontend trees

- **Decision:** `eslint.config.mjs` globally ignores `python/**`, `.motis/**`,
  `.agents/**` and `.playwright-cli/**`.
- **Why:** `npm run lint` (eslint with no arguments) walked the gitignored 3.6 GB
  `.motis` install and the Python virtualenv and did not finish. With the ignores
  it completes in seconds.
- **Where:** `eslint.config.mjs`.

### 17. `AGENTS.md` was partially updated even though Phase 4 owns it

- **Decision:** the Layout, Commands and Data pipeline sections now describe the
  Next stack and the removed `src/data` copy.
- **Why:** those sections pointed at files this layer deletes, so leaving them
  would make the repository's working agreement wrong. Phase 4's full rewrite can
  supersede it.
- **Where:** `AGENTS.md`.

### 18. No JavaScript test framework was added

- **Decision:** `src/App.test.js` is deleted and nothing replaces it.
- **Why:** the deleted test asserted `/learn react/i`, which the app never
  rendered, so it was already red. The plan specifies no JS tests for this layer,
  and `.agents/EXECUTION.md` puts rendering verification in manual
  `playwright-cli` checks rather than the test suite.
- **Where:** deleted `src/App.test.js`.

### 19. shadcn's generated files are kept as generated

- **Decision:** `components/ui/button.tsx`, `components/ui/card.tsx`,
  `lib/utils.ts`, `components.json` and the `shadcn` runtime dependency are
  unmodified from `shadcn init`/`add`.
- **Why:** they are the design system's defaults; hand-editing them would defeat
  using shadcn at all. `components.json` has `"rsc": false`, which is what the CLI
  chose for this project.
- **Where:** `components/ui/`, `lib/utils.ts`, `components.json`, `package.json`.

### 20. The baseline screenshots were staged, not committed

- **Decision:** `git add .agents/baseline/` only.
- **Why:** the layer brief says commits are made by the orchestrator. The
  directory is also being written by a concurrent orchestrator process, which is
  adding `next-*` comparison captures beside the `cra-*` baseline ones; the
  staging therefore includes whatever was present at the time.
- **Where:** `.agents/baseline/`.

### 21. `cn` was removed from `CityPage`, not routed through `@/lib/utils`

- **Decision:** the Live Status anchor uses
  `className={buttonVariants({ size: "sm", className: "mt-3" })}`; the component no
  longer imports `cn`.
- **Why:** `cn` was used once, only to append the static `mt-3` to
  `buttonVariants(...)`. `cva`'s returned function already merges a `className`
  prop into the result, so the class string is identical. `lib/utils.ts` exists but
  is an unreferenced re-export of the same package, so importing through it would
  have kept a one-use indirection rather than removing the need for it.
- **Where:** `components/city-page.tsx`.

### 22. The card list keeps `key={index}` because no domain field is unique

- **Decision:** `key={index}` is retained, with a comment stating why.
- **Why:** the CRA used `key={card.city}`, but the generated JSON repeats
  destinations — from Hamburg, Würzburg appears four times with the same `city` and
  `destination_stop` — so neither the name nor the stop id is unique. The rendered
  list is a prefix of the fixed dataset (`slice(0, visibleCount)`), so indices never
  shift, making the row index the only unique key. Expansion state is keyed by the
  same index for the same reason.
- **Where:** `components/city-page.tsx`.

## Review outcome

Adjudication of the reviewer's findings for this layer. Each entry gives the
finding, the ruling, and what changed. Where a ruling reverses an earlier
decision, the entry names the item it supersedes.

- **F1 (accepted):** `components.json` `"rsc"` is now `true`. The already
  generated components were not regenerated, so this only affects future
  `shadcn` runs. Supersedes item 19's `rsc: false` note.
- **F2 (accepted):** `latitude`/`longitude` were removed from `OriginCity` and
  from all seven manifest entries; they had no layer-3 consumer. Supersedes
  item 3.
- **F3 (accepted):** `origin_stop` was removed from the `Destination` type. The
  generated JSON still carries the key; nothing reads it.
- **F4 (accepted):** the redundant `01-home.png`, `02-about.png` and
  `03-origin-hamburg.png` were removed. Every named `cra-*` and `next-*`
  comparison image is kept.
- **F5 (accepted):** `shadcn` and `tw-animate-css` moved from `dependencies` to
  `devDependencies`; `package-lock.json` refreshed with
  `npm install --package-lock-only`. Nothing else moved.
- **F6 (accepted, semantic only):** the displayed city title in Home and
  CityPage now sits in an `<h2>` inside `CardTitle`. Tailwind's preflight resets
  heading size, weight and margin to inherit, so the rendered text is unchanged;
  the generated `card.tsx` was not touched and no page `<h1>` was added, matching
  CRA.
- **F7 (accepted):** the route comment now states only that `/health` proves
  native DuckDB reads `city.parquet`; the `duckdb.ts` path comment now states
  only the tracing reason, not layer-4 history.
- **F8 (accepted):** the self-referential `--font-sans: var(--font-sans)` is
  gone. The system stack is defined once in `@theme inline` and the duplicate
  `:root` declaration is removed. The stack and the visuals are unchanged.
- **Informational — `lib/utils.ts` (keep):** it is the `components.json` CLI
  alias target. Not deleted; the generated UI components are not hand-edited.
- **Informational — DuckDB tracing (keep):** `next.config.ts` tracing is
  unchanged; no churn.
